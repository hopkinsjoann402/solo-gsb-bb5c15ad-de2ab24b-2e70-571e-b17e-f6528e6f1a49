# 短片场记 · 连续性校验 + 现场拍摄排程

面向短片拍摄的场记工具，包含两个相互独立又共享场景数据的模块：

1. **连续性校验**：以**故事时间 + 同刻序号**组织场景（与实际拍摄顺序无关），为角色/道具建立状态字段，录入每个场景开拍前的**期望快照**与结束后的**显式状态变更**；系统自动按故事线**重放**全部变更，逐字段比对「推导状态 vs 期望快照」，标出**首次分歧及其来源场景**，并在任何顺序/快照/变更调整后**自动重算**。
2. **现场拍摄排程**：场景可填写**拍摄地点、预计分钟数、不可提前的故事序号**；系统按**拍摄日期**生成**确定性**排程——在满足故事顺序约束与**锁定场次**的前提下，优先**合并同地点场景、最小化地点切换**，逐日展示每次地点切换（含切换/不合并的原因）与各类冲突；用户可锁定/解锁场次、调整拍摄日期与单日时长后**重新计算**。排程**不会改动**连续性校验的故事时间线。

技术栈：TypeScript · React (Vite) · Express · SQLite (better-sqlite3)

## 一键启动（Docker）

```bash
docker compose up --build
```

启动完成后，浏览器访问：

- **http://localhost:8080** —— 打开后在顶部选项卡进入「现场拍摄排程」「故事时间线」「冲突列表」等页面。

健康检查：`http://localhost:8080/api/health`。

- 依赖安装、前端构建、SQLite 建库建表、演示数据写入全部随容器启动自动完成，无需任何手工步骤。
- 数据库文件持久化在命名卷 `continuity-data` 中（容器内路径 `/app/data/continuity.db`）。
- 旧版 Compose 可使用 `docker-compose up --build`。

## 配置项（均为环境变量，均有默认值）

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `8080` | HTTP 服务端口（Compose 已映射 `8080:8080`） |
| `DATABASE_PATH` | 容器内 `/app/data/continuity.db`；本地 `./data/continuity.db` | SQLite 数据库文件路径，启动时自动建目录、建表 |
| `SEED_DEMO` | `1` | 首次启动且库为空时写入演示数据（含两处刻意制造的连续性冲突，以及多地点、顺序约束、锁定场次的排程示例）；置 `0` 关闭 |

修改端口示例：`docker compose up --build` 前编辑 `docker-compose.yml` 的 `ports`，或本地运行时 `PORT=9000 npm start`。

## 本地开发（可选，不用 Docker）

```bash
npm run setup   # 安装 server 与 client 依赖
npm run dev     # 同时启动后端 :8080 与前端 :5173（/api 已代理）
```

访问 http://localhost:5173 。生产模式本地运行：`npm run build && npm start`（后端直接托管前端产物，端口同 `PORT`，访问 http://localhost:8080 ）。

## 功能与使用流程

### A. 连续性校验

1. **对象与字段**：建立角色/道具，为每个对象定义状态字段（key、显示名、初始值），如「林雪 · 服装 = 蓝色风衣」。
2. **场景管理**：按 `故事时间`（可排序字符串，建议 `D01 21:00` 格式）+ `同刻序号` 录入场景；为每个场景填写：
   - **期望快照**：该场景开拍前，某对象某字段应有的值（留空表示不校验该字段）；
   - **显式状态变更**：该场景结束后生效的状态改写（如「旧怀表 · 表盖 → 打开」）。
3. **故事时间线**：系统从字段初始值出发，按 `(故事时间, 同刻序号)` 重放所有场景：每个场景开拍前逐字段比对推导状态与期望快照，随后应用该场景的显式变更。每条比对都标注推导值的**来源**（初始值或某场景的变更）。
4. **冲突列表**：汇总所有不一致，可按对象筛选、可只看每个「对象+字段」的**首次分歧**，并给出造成该推导值的**来源场景**——修复首次分歧后重算，后续连锁分歧往往随之消除。
5. **自动重算**：校验结果由服务端在每次请求时现算，任何场景顺序、快照、变更、字段的调整保存后立即反映到时间线与冲突列表。

### B. 现场拍摄排程（与故事时间线相互独立）

1. **场景排程信息**（在「场景管理」中填写）：
   - **拍摄地点**：自由文本，同名地点视为同一处（如 `A 棚 · 公寓内景`）；
   - **预计分钟数**：该场的拍摄时长；
   - **不可早于故事 #**：该场只能在故事线第 `1..N` 场**全部拍完之后**拍摄（`0` = 无约束）。故事序号由 `(故事时间, 同刻序号)` 确定性排名，直接展示在场景卡片上。
2. **排程设置**：在「现场拍摄排程」顶部维护**拍摄日期列表**与**每个拍摄日的预计可用分钟数**。
3. **确定性排程规则**：服务端每次请求按固定规则现算（相同输入必得相同结果）：
   - 锁定场次固定为锚点；逐日、逐空位贪心选择；
   - 候选中**优先当前地点的同地点场景**（合并、零切换）；必须切换时选择**现在可连续拍摄同地点场次最多**的地点，以最小化全程切换次数（所有并列均按故事序号/地点名/场景 id 确定地打破）；
   - 若提前拍某场会导致未来必须折返同地点（其同地点伙伴受故事顺序约束、要等更晚拍摄日的锁定场次之后才能拍），当日会提前收工并说明原因。
4. **切换与冲突展示**：逐日列出场次、分钟区间与合并标记；每次**地点切换 / 跨日延续 / 提前收工**都给出文字说明；冲突类型包括：
   - **容量冲突**：某日累计分钟数超出单日预计，或所有拍摄日都装不下（追加到最后一个拍摄日）；
   - **顺序冲突 / 锁定冲突**：自由场次或锁定场次在其前置故事拍完之前拍摄；
   - **锁定重叠 / 锁定失效**：同一拍摄日同一位置锁定了多场，或锁定到已删除的拍摄日期。
5. **锁定 / 解锁 / 重算**：在排程卡片上把任一场次锁定到「某拍摄日的第 N 个拍摄位置」，或解锁；调整日期、单日时长后点击「保存设置并重算」，排程立即按新约束确定性重算。

> 两个模块共享场景但互不干扰：排程只读取故事顺序、地点、时长与锁定信息，**不读取也不修改快照与状态变更**；无论如何排程，「故事时间线」的连续性重放结果都保持不变。

## API 摘要

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET/POST | `/api/entities` | 对象列表 / 新建（含字段） |
| PUT/DELETE | `/api/entities/:id` | 更新（字段增删改，key 变更自动迁移历史数据）/ 删除 |
| GET/POST | `/api/scenes` | 场景列表（按故事时间排序，含地点/预计分钟/不可早于序号/故事序号）/ 新建 |
| PUT/DELETE | `/api/scenes/:id` | 更新（含故事时间、同刻序号、地点、预计分钟数、不可早于故事序号）/ 删除 |
| PUT | `/api/scenes/:id/snapshot` | 整体替换该场景的期望快照 |
| PUT | `/api/scenes/:id/changes` | 整体替换该场景的显式变更 |
| GET | `/api/continuity?entityId=` | 重放并返回时间线比对结果与冲突列表（可按对象过滤） |
| GET | `/api/schedule` | 按拍摄日返回确定性排程、切换/收工事件与冲突原因 |
| GET/PUT | `/api/schedule/settings` | 读取 / 更新拍摄日期列表与单日预计分钟数 |
| PUT | `/api/schedule/:id/lock` | 锁定场次到 `{date, ordinal}`（位置冲突返回 409），返回最新排程 |
| DELETE | `/api/schedule/:id/lock` | 解锁场次，返回最新排程 |

## 项目结构

```
├── Dockerfile             # 多阶段构建：前端产物 + 后端编译 + 生产依赖
├── docker-compose.yml     # 一键启动
├── server/                # Express + better-sqlite3
│   └── src/
│       ├── db.ts          # 连接、建表/旧库升级、演示数据（含排程字段、拍摄日期、锁定）
│       ├── engine.ts      # 连续性引擎：重放、逐字段比对、首次分歧与来源
│       ├── schedule.ts    # 排程引擎：故事序号、锁定锚点、同地点合并贪心、切换/冲突解释
│       ├── routes.ts      # REST API（对象 / 场景 / 连续性 / 排程 / 锁定）
│       └── index.ts       # 启动：初始化 DB、挂载 API、托管前端
└── client/                # React + Vite
    └── src/
        ├── App.tsx        # 选项卡、对象筛选、数据加载与自动重算
        ├── api.ts         # 前后端共享类型与请求封装
        └── components/    # 时间线 / 冲突列表 / 现场排程 / 场景管理 / 对象与字段
```
